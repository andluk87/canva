# WebSocket API — релиз 0.3

Путь: `/api/projects/{id}/live`. Протокол ws/wss, same-origin cookie `forma_session`, обязательный Origin с тем же Host. Не передавайте токены в URL.

Handshake: 401 без сессии, 403 для чужого Origin, 404 для отсутствующего/недоступного/удалённого проекта, 429 при лимите соединений. Секретные поля в сообщениях отсутствуют. Клиент/сервер передают JSON; Yjs update и state vector закодированы base64.

Сервер → клиент:

- `hello`: `{type,id,epoch,role,revision,update,vector}`. Полное состояние, vector для отправки только недостающих изменений, идентификатор соединения и серверная роль.
- `update`: `{type,update,revision}`. Принятое изменение другого участника или REST API.
- `ack`: `{type,seq,revision}`. Подтверждает транзакционное сохранение конкретного клиентского update.
- `presence`: `{type,peers:[{id,userId,name,role,cursor}]}`. Имя и роль берутся сервером. Cursor равен null или `{x,y,page}` в координатах документа.
- `role`: `{type,role}`. Изменение серверных прав.
- `error`: `{type,error}`. Изменение не принято; не показывать статус успешного сохранения.

Клиент → сервер:

- `update`: `{type,epoch,seq,update,thumbnail?}`. seq — целочисленный номер отправки; thumbnail — PNG data URI до 400000 символов. Viewer не может отправлять изменения.
- `cursor`: `{type,cursor}`. Координаты ограничены 6000 px; cursor обновляется не чаще примерно 20 раз/сек.

Коды закрытия: 4003 — отзыв доступа/окончание сессии; 4009 — другой epoch; 1008 — некорректный документ/протокол/лимит; 1013 — слишком медленный получатель. При временном обрыве клиент переподключается, объединяет Y.Doc с hello и отправляет недостающую разницу. При отказе доступа/сбросе epoch автоматическая отправка прекращается, чтобы пользователь мог сохранить локальную копию JSON.

Клиентский adapter: `src/collaboration.ts`. Общая модель: `shared/collaboration.mjs`. Сервис: `server/realtime.mjs`. Нужен один backend; шардирование, горизонтальная синхронизация и посимвольный текст не входят в 0.3.

В 0.3 клиент сохраняет состояние Yjs и неподтверждённые правки в IndexedDB. Перезагрузка без сети и последующее восстановление используют тот же hello/vector/ack протокол; подробности и ограничения — [OFFLINE.md](OFFLINE.md).
