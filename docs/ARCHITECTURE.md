# Архитектура релиза 0.6.0

Browser → Express HTTP / WebSocket → SQLite + filesystem (один persistent Docker volume).

React 19 + TypeScript + Vite загружают редактор отдельным чанком. Fabric.js отвечает за объекты и рендеринг. Слой приложения управляет страницами, свойствами и сериализацией. Yjs объединяет совместные изменения и обеспечивает локальный UndoManager. PDF/PNG/JPG/SVG и PPTX генерируются браузером; для PPTX используется PptxGenJS, сложные слайды рендерятся Fabric целиком в PNG; Sharp на сервере проверяет, ограничивает, поворачивает и перекодирует загрузки в PNG. PWA-оболочка и IndexedDB позволяют открыть ранее посещённый проект без сети и сохранить правки до подключения.

## Документ и совместная работа

`projects.document = {pages:[{id,canvas:FabricJSON}]}` остаётся совместимым с первым релизом. Объекты имеют постоянные id; копирование выдаёт новые id, в том числе вложенным объектам группы. Старые документы получают id при открытии совместной сессии. Размер проекта общий для страниц, изображения встроены в документ. Градиенты, обводки, тени, скругления, crop, clipPath и фильтры сохраняются как стандартные свойства Fabric и участвуют в общей синхронизации и Undo. Страницы также содержат необязательные `notes` (до 10 000 символов) и `transition` (`none`/`fade`/`slide`); эти метаданные сохраняются в JSON/версиях и синхронизируются отдельными полями существующей страницы Y.Map. Это исключает гонку создания вложенного контейнера на legacy-документах; прежний вложенный формат читается как fallback, явное удаление отмечается null.

В Y.Doc название хранится в `project`, страницы — в Y.Map `pages`. Каждая страница содержит метаданные canvas и Y.Map объектов. Свойства объекта хранятся независимо, поэтому изменение координат одним редактором не отменяет изменение цвета другим. Порядок задают позиция и стабильный id для разрешения совпадений. Конкурентное изменение одного свойства разрешается детерминированно по правилам Yjs. Текст — строковое свойство целого блока, не Y.Text: посимвольное совместное редактирование не реализовано.

Клиент отправляет только разницу относительно действительно показанного состояния. Неизвестные локальной вкладке чужие объекты/поля не перезаписываются. Во время перетаскивания или ввода текста отображение входящих изменений откладывается до завершения действия, после чего берётся актуальный объединённый Y.Doc. UndoManager отслеживает только локальные транзакции; чужие действия не входят в Undo.

Сервер сначала применяет update к отдельной копии состояния, проверяет документ и лимиты, затем в одной SQLite-транзакции сохраняет JSON, полное состояние Yjs и revision. Только после COMMIT отправляется ack. Непринятое обновление не изменяет действующий документ. Таблица `collaboration` создаётся идемпотентно без удаления старых данных. В ней сохраняется epoch сессии, поэтому обычный рестарт и повторное подключение не сбрасывают историю CRDT.

Контрольная версия создаётся перед первым принятым изменением комнаты и затем не чаще раза в 30 секунд при изменении содержимого. Хранятся последние 30 версий. REST-обновления сохраняют проверку revision, а активные комнаты получают их через Yjs. Метаданные без изменения документа не сбрасывают epoch. Внешняя замена документа при неактивной комнате может создать новый epoch.

## PWA, локальное сохранение и переподключение

В production Vite генерирует `/offline-assets.json` и версионированный `/sw.js`. Service worker заранее кэширует оболочку, JavaScript и CSS; навигация использует сетевой ответ с локальной оболочкой при недоступности сети. `/api/` исключён из service-worker-кэша, поэтому приватные ответы и cookies не попадают в общий кэш оболочки. Регистрация service worker доступна в защищённом контексте — HTTPS либо localhost; обычный HTTP по удалённому IP позволяет работать онлайн, но не обеспечивает офлайн-перезагрузку.

IndexedDB `forma-offline-v1` содержит `projects` и `documents`. Ключи включают userId и projectId. Полный документ записывается после открытия проекта; список серверных метаданных не считается локальной копией содержимого непосещённого проекта. Для Yjs сохраняются полное бинарное состояние, epoch, последняя роль, revision и флаг неподтверждённых изменений. Записи сериализуются через очередь; статус «сохранено на устройстве» выводится после завершения транзакции IndexedDB. Ошибка записи показывает отдельный статус и предложение экспортировать JSON.

Локально сохранённое представление аккаунта позволяет восстановить интерфейс при отсутствии сети в течение семи дней после успешной проверки; оно не заменяет серверную аутентификацию. Офлайн работа требует того же браузерного профиля, ранее проверенного аккаунта и доступного хранилища. Локальные данные не зашифрованы приложением и не являются резервной копией сервера. Браузер может удалить их, например при очистке сайта или нехватке места. Выход очищает данные текущего аккаунта на этом устройстве; удалённое стирание копии на отключённом устройстве не реализовано.

WebSocket автоматически переподключается с задержкой 0,5–10 секунд и реагирует на возвращение сети. Клиент восстанавливает локальный Y.Doc, объединяет его с hello сервера и отправляет недостающую разницу. Сервер повторно проверяет cookie и актуальные права. При несовместимом epoch с неподтверждёнными правками автоматическая отправка прекращается и предлагается экспорт JSON. Если локальных правок нет, новый серверный epoch заменяет устаревший локальный документ. Отзыв права редактирования также останавливает отправку.

Офлайн поддерживается редактирование уже открытых проектов, а не все серверные функции. Регистрация, настройки аккаунта, загрузка новых серверных файлов, массовое создание, серверная библиотека личных шаблонов и публикация требуют сети. Подробности CRDT-протокола: [REALTIME.md](REALTIME.md); описание переподключения там относится также к сохранённому в IndexedDB состоянию текущего релиза. Ограничения и очистка локальных данных: [OFFLINE.md](OFFLINE.md).

## Расширенные инструменты и SVG

`AdvancedTools` использует стандартные классы Fabric `Gradient`, `Shadow` и фильтры изображения. Коррекция пересчитывается от оригинала; сброс удаляет только управляемые этой панелью фильтры. Операции расположения учитывают границы объектов после преобразований, временно снимают ActiveSelection и восстанавливают её после изменения координат.

До парсинга SVG проверяется XML и разрешённый набор тегов/атрибутов. Скрипты, HTML, внешние ресурсы, DTD/сущности, неподдерживаемый CSS и циклы ссылок отклоняются. Есть лимиты размера, числа узлов, вложенности и цепочек ссылок. Исходный SVG не вставляется в DOM и не используется для сетевых загрузок. Экспорт строится из снимка документа во временном StaticCanvas с исходными размерами, независимо от масштаба рабочего холста. Ограничения поднабора: [ADVANCED.md](ADVANCED.md).

## Фото, диаграммы и визуальные таблицы

`ImageTools` задаёт кадр целыми пикселями исходного `_originalElement`, независимо от возможного canvas после фильтрации. Валидация выполняется до изменения объекта. Изменение рамки сохраняет центр в координатах родителя, масштаб, угол и отражение. `Circle`/`Rect` в относительном `clipPath` создают маски, которые подстраиваются под новый кадр; другие существующие clipPath сохраняют геометрию. Исходный `src` не заменяется и не перекодируется. Поэтому **скрытые пиксели остаются доступны в исходнике, JSON и публичном снимке**; crop/маски не являются удалением конфиденциальных данных. Подробности: [IMAGE_TOOLS.md](IMAGE_TOOLS.md).

`DataTools` превращает проверенный CSV в `Group` с нативными `Rect`, `Line`, `Path`, `Circle` и текстом. `formaData` хранит версию модели, исходные строки/заголовки, тип, палитру, заголовок и базовый размер. Метаданные сериализуются и позволяют заново построить выбранную группу, сохранив её id, трансформации, блокировки и порядок слоя. Разгруппированные дочерние фигуры остаются обычными объектами; правки данных выполняются через исходную группу, а не через таблицу ячеек.

Столбчатые и линейные диаграммы поддерживают отрицательные значения и общую нулевую базу; круговые — положительные доли. Модель ограничена 30 строками, 8 столбцами таблицы, 2 столбцами диаграммы, 12 строками круговой диаграммы и 100 КБ CSV. Длинные подписи визуально сокращаются, но остаются в исходной модели/CSV. Формулы, зависимости ячеек, пересчёт, XLSX и сервер внешних данных отсутствуют. Это визуальные объекты дизайна, не spreadsheet. Контракт: [DATA_TOOLS.md](DATA_TOOLS.md).

## Презентации и экспорт PPTX

`SlideSettings` редактирует заметки/переход текущей страницы. `PresentationViewer` создаёт отдельные StaticCanvas для отображения: редактируемый холст не используется для показа и не изменяется. Viewer поддерживает клавиатуру, таймер, чёрный экран, запрос fullscreen и системный reduced motion. Заметки показываются в том же окне, поэтому при демонстрации всего экрана их увидит аудитория; отдельного окна докладчика нет.

`exportPptx` создаёт настоящий Office Open XML через ленивый импорт `pptxgenjs`. Пропорции исходного проекта сохраняются; notes становятся стандартными notesSlide-частями. Слайд экспортируется целиком в одном из двух режимов: совместимые простые однострочные тексты, прямоугольники и круги становятся нативными редактируемыми объектами; наличие сложного элемента переводит **всю страницу** в PNG, с максимальной длинной стороной 4096 px. Так сохраняется порядок и внешний вид сложных групп/эффектов, но редактировать отдельные элементы снимка в PowerPoint нельзя.

Группы диаграмм/таблиц, изображения, маски, градиенты, тени, обводки, повороты и сложный текст вызывают растровый режим. Внешние изображения и SVG data URI отклоняются до рендеринга; нужны встроенные PNG/JPG/WebP. Шрифты не встраиваются, метрики нативного текста зависят от Office/устройства. Переходы Forma остаются только в браузерном показе. Импорта PPTX и полной совместимости с PowerPoint не заявляется. JSZip используется в Node-тестах для чтения реальных ZIP/XML-частей. Описание: [PRESENTATIONS.md](PRESENTATIONS.md).

## Приватная библиотека шаблонов

`personal_templates` хранит самостоятельный снимок сохранённого серверного проекта с владельцем, названием, категорией, размерами, числом страниц, thumbnail, bytes и revision. Источником может быть доступный владельцу библиотеки проект с ролью owner/editor. Сохранение, явное обновление и создание проекта выполняются транзакционно; PATCH требует текущую revision и возвращает 409 при конфликте. Пределы на аккаунт — 100 шаблонов и 50 МиБ снимков с превью.

API `/api/personal-templates` позволяет читать только собственную библиотеку, искать по названию/категории, сохранять снимок, изменять метаданные/явно заменять содержимое, удалять и `POST /:id/instantiate` создавать самостоятельный проект. Исходные участники, комментарии и история не копируются. Шаблон сохраняет снимок даже после изменения, удаления или отзыва доступа к исходному проекту: это уже созданная копия. Общего каталога, marketplace, командного доступа и офлайн API библиотеки нет. Документация: [PERSONAL_TEMPLATES.md](PERSONAL_TEMPLATES.md).

## Массовое создание и публичные снимки

CSV разбирается общим модулем клиента/сервера. Поддерживаются UTF-8/BOM, запятая и точка с запятой, кавычки и многострочные ячейки. Переменные заменяют только текст, включая вложенные группы и все страницы. Исходный документ остаётся неизменным. Все строки проверяются до записи; до 50 новых проектов создаются одной транзакцией. История, участники, комментарии и прочие пользовательские метаданные источника не копируются. XLSX, формулы и подстановка изображений отсутствуют. Лимиты и API: [BULK.md](BULK.md).

Таблица `publications` хранит состояние публичного токена; `publication_snapshots` — неизменяемые версии нормализованного JSON и SHA-256. Публикация строится из сохранённой серверной ревизии, требует владельца и не обновляется вслед за приватными правками автоматически. Случайный токен имеет 256 бит; срок и отзыв проверяются при каждом новом обращении. Корзина и удаление источника также закрывают доступ. Отзыв не стирает уже полученную копию у читателя.

Гостевой ответ содержит только опубликованное содержимое и необходимые метаданные. Неизвестные поля и приватные ID удаляются; изображения должны быть встроены, проходят проверку и перекодирование Sharp. Гостевой просмотр не загружает приватные файлы или внешние ресурсы. Ответы используют `no-store`, `no-referrer` и запрет индексации. Публикация снимка не создаёт самостоятельный сайт и не скрывает текст, явно размещённый автором на холсте. Метаданные страниц notes/transition в публичный ответ не включаются; crop/clipPath отображаются, но оригинальные встроенные пиксели изображения сохраняются. Исходная модель `formaData` не нужна гостевому рендерингу: отображаются нативные дочерние фигуры/текст. Подробности: [PUBLISHING.md](PUBLISHING.md).

## Авторизация и TOTP

Пароль: scrypt с индивидуальной случайной солью. Сессия действует 7 дней, в БД хранится SHA-256 токена. Cookie HttpOnly/SameSite=Lax; Secure включается через `COOKIE_SECURE`. HTTP-изменения проверяют Origin при наличии. WebSocket требует совпадающий Origin, действующую cookie и доступ к конкретному проекту при handshake.

Каждый WebSocket-пакет заново проверяет сессию и роль. Reader получает документ, но не может отправлять изменения. Доступ отзывается через закрытие соединений; смена роли доставляется в интерфейс. Выход из аккаунта закрывает его открытые соединения. Каждые 15 секунд heartbeat дополнительно проверяет сессии и удаляет зависшие соединения. Присутствие формируется сервером из аутентифицированной личности; клиент не может подставить чужое имя. Курсоры и присутствие не сохраняются.

Настройки позволяют изменить имя и пароль, увидеть собственные сеансы и отозвать их. Смена пароля завершает другие сеансы. Публичные идентификаторы сеансов основаны на HMAC и не являются токенами входа. Миграция добавляет метаданные сеансов и таблицу `account_security` без удаления старых данных.

TOTP соответствует RFC 6238: SHA-1, 6 цифр, период 30 секунд, допуск ±1 период и защита от повторного использования периода. Настройка требует текущего пароля, живёт 10 минут и активируется после подтверждения кода. Выдаются 10 резервных кодов, показываемых один раз и сохраняемых в БД только в виде хешей. Изменение защиты требует пароль и действующий второй фактор. Секреты TOTP зашифрованы AES-256-GCM ключом `DATA_DIR/account-security.key` с правами `0600`.

SQLite и `account-security.key` необходимо сохранять и восстанавливать вместе. Ключ хранится в том же volume, поэтому шифрование не заменяет защиту сервера и резервных копий. OAuth, подтверждение email и восстановление пароля по почте отсутствуют. Полный контракт: [ACCOUNTS.md](ACCOUNTS.md).

## Лимиты и эксплуатация

Основные лимиты: HTTP body 20 МБ, JSON-документ 15 МБ, upload 10 МБ / 25 Мп, 100 страниц, 2000 объектов на страницу, состояние Yjs 20 МБ, 500 WebSocket-соединений на процесс, 20 на пользователя, 100 сообщений/сек на соединение. Slow clients отключаются. Лимиты CSV и публичных снимков описаны в документации модулей. Глобальных квот хранения, промышленной DDoS-защиты и распределённых лимитов нет.

Multi-stage Dockerfile: `npm ci` по lockfile с сохранением TLS/integrity, до четырёх повторов сетевых запросов, backoff 2–20 секунд, fetch timeout 120 секунд и maxsockets=8. Кэш npm — BuildKit cache mount; установка, tsc/Vite и offline prune dev dependencies выполняются в одном RUN, поэтому очистка кэша между сборками не ломает prune; runtime Node 24 под непривилегированным пользователем, persistent volume, healthcheck. Сервис публикует порт 8192. Нужен reverse proxy с HTTPS, поддержкой WebSocket Upgrade и сохранением Host/Origin; для HTTPS задаётся `COOKIE_SECURE=true`.

Схема предполагает **один backend-процесс**: Redis/pubsub для нескольких процессов не реализован. Yjs tombstones пока не компактизируются; при достижении лимита состояния следует экспортировать JSON и создать новый проект. Схема подходит для пилота, но не заменяет PostgreSQL/Redis/S3/worker архитектуру полного ТЗ. Перед production нужны мониторинг, квоты, проверенные бэкапы и восстановление, аудит безопасности и нагрузочные испытания. AI, биллинг, видео и OAuth-провайдеры в архитектуру текущего релиза не подключены.

## Экспорт 0.5

`shared/export-options.mjs` проверяет номера, порядок страниц и пиксельные бюджеты. `src/export/ExportDialog.tsx` получает неизменяемый снимок при открытии. `render.ts` последовательно рендерит временные StaticCanvas, формирует ZIP через JSZip и проверяет объём. Закрытие окна отменяет загрузку и блокирует позднее скачивание. JPG сводится на белый canvas; PDF сохраняет исходный размер бумаги при изменении детализации. Предпросмотр CSV использует отдельный StaticCanvas без записи в исходник.

## Бренд-наборы 0.6

`server/brand-kits.mjs` создаёт отдельную таблицу `brand_kits` без изменения прежнего поля `users.brand`. Последнее хранит активную палитру/типографику и необязательный `kitId`. Наборы приватны, используют revision и транзакционные квоты 20 наборов / 30 МиБ. Логотипы нормализуются Sharp и хранятся внутри набора как PNG data URL; после асинхронной обработки повторно проверяются права, версия и квоты. В документ вставляется независимая копия. Список API исключает payload логотипов.

`src/brand/BrandLibrary.tsx` управляет наборами, `BrandPanel.tsx` выбирает и применяет их в редакторе. Чистые правила параметров/патчей — `shared/brand.mjs`. Один синхронный проход по нативным объектам публикуется одним действием Yjs и поддерживает локальный Undo. Загрузка и поздние ответы защищены поколением запроса/временем жизни компонента.
