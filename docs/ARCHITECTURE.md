# Архитектура первого релиза

Browser → Express API → SQLite + filesystem (один persistent Docker volume).

React 19 + TypeScript + Vite загружают редактор отдельным JS-чанком. Fabric.js — движок объектов, выделения и рендеринга, собственный слой приложения отвечает за страницы, историю, панели свойств и сериализацию. Это не собственный WebGL-движок из ТЗ. PDF/PNG/JPG генерируются в браузере; Sharp на сервере проверяет, ограничивает, поворачивает и перекодирует загрузки в PNG. Исходные пользовательские файлы на сервере не сохраняются.

## Модель документа

`projects.document = {pages:[{id,canvas:FabricJSON}]}`. Объекты сохраняются раздельно с координатами, трансформациями, текстом и свойствами. Размер проекта общий для всех страниц. Встроенные изображения — data URI. Снимок JSON создаётся после изменения объекта, редактирования текста или операции страницы. Локальная история содержит до 80 состояний, не сохраняется между вкладками. Сервер сохраняет 30 предыдущих состояний документа.

Автосохранение запускается через секунду после изменения. Запросы в одной вкладке сериализованы, revision проверяется сервером перед обновлением; SQLite transaction атомарно записывает текущий документ и его предыдущую версию. При конфликте 409 сохранение блокируется до обновления проекта. В UI ошибка видна явно. При несохранённых данных срабатывает beforeunload. Потеря сети не означает успешного сохранения; при событии online запрос повторяется. Постоянного локального офлайн-хранилища нет.

## Авторизация

Пароль: scrypt с индивидуальной случайной солью, constant-time comparison. Серверная сессия действует 7 дней, в БД хранится SHA-256 токена. Cookie HttpOnly/SameSite=Lax; Secure включается через COOKIE_SECURE. Перед изменением проверяется Origin при наличии. Проект видят только владелец и явно добавленные участники. Viewer не может изменять документ/комментарии. Editor не управляет доступом и удалением проекта. Все изменения без проверки прав возвращают 401/403/404. Выход отзывает текущую сессию. Uploads доступны только владельцу; для работы в общих проектах редактор встраивает изображения в документ.

Ограничения: лимит тела 20 МБ, документ 15 МБ, файл 10 МБ, декодирование 25 Мп, ограничение login/register по IP 60 запросов за 15 минут в памяти процесса. Reverse proxy не считается доверенным автоматически. Это не полноценная защита от DDoS; глобальные квоты хранения, аудит, password reset, email verification и распределённые лимиты требуют следующего этапа.

## Хранение

Схема создаётся идемпотентно при старте. Таблицы users, sessions, projects, members, versions, assets, comments. Есть внешние ключи, WAL, unique email. Удаление проекта каскадно удаляет доступ, версии и комментарии; пользовательские изображения сохраняются в личной библиотеке. Миграций обновления схемы пока нет (первый релиз).

## Эксплуатация

Multi-stage Dockerfile: npm ci по lockfile, tsc, Vite, prune dev dependencies; runtime Node 24, непривилегированный пользователь, persistent volume, healthcheck. Один контейнер, без внешних БД и очередей. Схема подходит для пилотного экземпляра, но не заменяет PostgreSQL/Redis/S3/worker архитектуру полного ТЗ. Перед production нужны TLS, квоты, бэкапы с испытанием восстановления, мониторинг, аудит безопасности и нагрузочные испытания.
