# ТЕХНИЧЕСКОЕ ЗАДАНИЕ
## Разработка платформы онлайн-дизайна — функционального аналога Canva

**Версия:** 1.0  
**Дата:** 19.10.2026  
**Тип продукта:** SaaS / Online Design Platform  
**Платформы:** Web, Mobile Web, iOS, Android  
**Цель:** Разработать масштабируемую платформу для создания, редактирования, совместного использования и публикации визуального контента.

**Уровень реализации:** Максимально полное функциональное соответствие Canva. Разработка ведётся независимо, без использования её закрытого кода, товарных знаков и нелицензированного контента.

**Статус документа:** Базовое ТЗ для проектирования, оценки бюджета, декомпозиции задач и последующей разработки.

# 1. ОБЩЕЕ ОПИСАНИЕ ПРОЕКТА

## 1.1. Концепция

Необходимо разработать собственную онлайн-платформу графического дизайна, предоставляющую пользователям возможность создавать профессиональные визуальные материалы без установки специализированного программного обеспечения.

Платформа должна функционировать преимущественно в браузере и предоставлять визуальный редактор по принципу Drag & Drop.

Основные функциональные направления:

1. Графический редактор.
2. Редактор презентаций.
3. Редактор видео и анимаций.
4. Редактор фотографий.
5. Редактор документов.
6. Редактор таблиц и диаграмм.
7. Онлайн-доски для совместной работы.
8. Конструктор сайтов.
9. Библиотека шаблонов.
10. Библиотека изображений, иконок и других материалов.
11. AI-инструменты для создания и редактирования контента.
12. Совместное редактирование проектов.
13. Управление командами и брендами.
14. Импорт и экспорт файлов.
15. Публикация материалов.
16. Система подписок и платных возможностей.
17. Маркетплейс приложений и интеграций.
18. Инструменты массовой генерации дизайнов.
19. Офлайн-редактирование.
20. Административная панель.
21. Печать и заказ физических продуктов.
22. Образовательные и корпоративные возможности.

Каждый модуль должен интегрироваться в общую экосистему.

## 1.2. Основные требования

- Полноценное редактирование через браузер.
- Визуальный интерфейс с минимальным порогом входа.
- Поддержка многостраничных документов.
- Отображение результата в режиме WYSIWYG.
- Автоматическое сохранение изменений.
- Обратимые действия Undo/Redo.
- Совместная работа нескольких пользователей.
- Экспорт в распространённые форматы.
- Адаптация к различным разрешениям экранов.
- Поддержка большого количества пользователей.
- Возможность расширения функциональности без переписывания основного редактора.

## 1.3. Критерий функционального соответствия

До разработки команда должна сформировать реестр функций референсного продукта на согласованную дату.

Для каждой функции указываются:

- Уникальный идентификатор.
- Название.
- Экран и пользовательский сценарий.
- Описание поведения.
- Состояния интерфейса.
- Действия пользователя.
- Ожидаемый результат.
- Приоритет.
- Тест-кейсы.
- Статус реализации.

Требование «полная копия» считается выполненным только после прохождения согласованной матрицы функционального соответствия. Возможности, появившиеся у референсного продукта после фиксации перечня, оформляются отдельными изменениями к ТЗ.

# 40. ФИНАЛЬНОЕ ТРЕБОВАНИЕ К РАЗРАБОТЧИКАМ

Разрабатываемая система не должна представлять собой демонстрационный интерфейс, статический шаблон или набор неработающих кнопок.

Каждая заявленная функция должна иметь:

- Рабочий интерфейс.
- Реализованную бизнес-логику.
- Необходимую серверную обработку.
- Постоянное хранение данных, если оно требуется.
- Проверку прав и ограничений.
- Корректную обработку ошибок.
- Тесты.
- Документацию.
- Проверяемые критерии приёмки.

Если пользователь создаёт дизайн, изменения должны сохраняться. Если он изменяет объект, результат должен корректно отображаться. Если он экспортирует файл, результат должен соответствовать содержимому документа. Если он приглашает другого пользователя, доступ должен контролироваться сервером.

**Главный принцип: реализовать работающий продукт с полноценной функциональностью, а не визуальную имитацию Canva.**
